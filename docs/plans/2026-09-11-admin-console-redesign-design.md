# 管理后台全量信息架构与交互重构设计

日期：2026-09-11
状态：已获用户批准，采用方案 A（一次性全量重构）
范围：仅重构管理后台前端；不改变后台业务能力、API 契约、数据库模型或权限边界。

## 1. 设计目标

- 让管理员围绕任务工作，而不是围绕实现模块工作。
- 首屏优先呈现当前任务的状态、下一步动作和异常，不用装饰性 Hero 消耗空间。
- 把功能归位：运营、配置、集成、账户互不混杂；相关能力在一个任务页内完成。
- 所有可操作状态具备明确反馈：加载、空态、成功、失败、危险操作确认、保存未提交。
- 桌面和移动端使用同一信息架构；移动端改为导航抽屉，表格提供可读的卡片/横向滚动降级。
- 保持现有 API/服务能力不变；旧 `/admin/dashboard?tab=...` 链接继续可用并映射到新路由。

## 2. 真实审计结论

### 横向问题

1. 每页都有大 Hero、重复标题和相同的「所有操作集中在左侧导航」提示，真实内容被推到首屏以下。
2. 页面级标题与工作区内部标题/说明重复，项目、系统配置、激活码、消费、审计均存在套娃。
3. 10 个 tab 平铺，运营、销售、集成、设置混在一起；修改密码不应占据运营主导航。
4. 当前 tab 主要依赖客户端状态，分享、刷新、浏览器前进后退不稳定；需 URL 可寻址。
5. `DashboardModal` 实测面板高度 858px、内容 overflow visible，项目创建时背景内容与弹框内容同时可见，层级与视觉遮罩不可靠；需统一 Radix Dialog/Sheet，并将焦点锁定、返回焦点、Escape、点击遮罩纳入验收。
6. 移动端实测抽屉背景与后方内容对比不足，导航点击后仍残留 dialog 状态；需验证关闭和焦点恢复。

### 各业务模块问题与重排

- **概览**：保留关键 KPI、最近异常、近期操作；趋势与运营洞察分区，不把每个指标做成同等权重的大卡。
- **项目**：列表是主内容；创建/编辑都用 Dialog，策略编辑作为项目详情中的独立「策略」区，不在列表行内塞多个按钮和长文本。
- **激活码**：将「生成」和「管理」合并为激活码工作区的两个明确子页/动作入口；生成表单分为核心字段、授权参数、高级换绑策略，策略默认折叠；列表筛选采用一个可收起的筛选栏，危险批量清理单独放到更多操作。
- **消费日志**：以排障为中心：筛选栏（项目、时间、requestId、machineId、激活码）+ 结果表 + 详情抽屉；自动刷新是工具栏开关，不占据 Hero。
- **审计**：只保留筛选、时间线/表格、导出；详情从行点击打开抽屉，避免把 detail JSON 直接塞入宽表。
- **购买中心**：拆成「商品」「订单」「支付渠道」三个子路由/子页；默认先看商品列表，创建商品用 Dialog；订单页以状态为主并提供清理超时订单；支付渠道按渠道卡片显示配置完整性和测试动作。
- **系统设置**：默认进入设置概览，但概览只做影响提示与未保存状态摘要；白名单、换绑策略、认证会话、系统展示、通知告警、高级配置使用同一设置导航 + 单一保存栏，不再重复 Hero 和嵌套卡片。
- **API 接入**：改为文档导航（概览、接口、示例、后台联调）+ 右侧固定目录/当前章节，不与运营 tab 的形式混用。
- **账户**：修改密码移入用户菜单，并保留可寻址的 `/admin/settings/security` 作为深链；成功后明确倒计时退出。

## 3. 新后台路由与兼容映射

新路由采用 App Router 页面边界，至少包含：

- `/admin/overview`
- `/admin/projects`
- `/admin/licenses/generate`
- `/admin/licenses`
- `/admin/consumptions`
- `/admin/audit`
- `/admin/integration`
- `/admin/shop/products`
- `/admin/shop/orders`
- `/admin/shop/payment`
- `/admin/settings`
- `/admin/settings/security`

现有 `/admin/dashboard?tab=stats|projects|generate|list|consumptions|auditLogs|apiDocs|shop|systemConfig|changePassword` 保留为兼容入口，由客户端/服务端重定向到对应新路由，避免旧书签失效。

## 4. 组件与状态架构

### AppShell

- `AdminShell`：桌面侧栏、移动端 Sheet、顶栏、面包屑、用户菜单、语言/主题切换。
- `AdminNav`：分组导航，当前路径驱动 active 状态，不再依赖手工 tab 状态。
- `PageHeader`：紧凑标题、描述、面包屑、主动作和次动作槽位；每页只允许一个。
- `PageToolbar`：筛选、搜索、刷新、导出、更多动作的标准排列。
- `PageSection`：统一标题/说明/内容间距；避免 Card 套 Card。
- `DetailDrawer` / `ConfirmDialog`：详情和危险操作使用统一焦点、遮罩、键盘行为。
- `DataTable` + `MobileRecordCard`：桌面宽表、移动端可读记录卡片或横向滚动。
- `EmptyState` / `ErrorState` / `LoadingState`：明确下一步动作，避免空白大块。
- `StickySaveBar`：设置页/复杂表单显示未保存数量、保存、重置和离开提示。

### 状态规则

- 列表筛选状态进入 URL query；分页、排序可复制。
- 页面主 tab/子页进入 pathname；浏览器后退可恢复上一个工作上下文。
- 创建/编辑 Dialog 打开时保存触发来源；关闭后返回原列表位置并刷新数据。
- 破坏性操作二次确认显示对象名、影响范围和不可逆性；提交中按钮锁定。
- 错误优先显示可读错误和恢复动作；保留 API 错误码用于诊断。
- API 请求失败不清空已有数据；显示 inline error + retry。

## 5. 视觉方向

- 使用现有 shadcn/Radix 组件和语义令牌，不继续叠加自定义 card 样式。
- 背景层次：页面 background → 内容 card → muted toolbar；禁止每个区块都使用强边框。
- 主动作每个页面最多一个 primary；危险动作使用 destructive 并放入更多菜单或确认对话框。
- 标题层级最多 H1 + section H2；描述文字缩短为任务提示，不写实现说明。
- 数字使用 tabular-nums；状态用 Badge，不用整块高饱和色抢焦点。
- 动画只用于导航/抽屉/对话框进入退出和加载反馈，不对数据卡片做无意义漂浮。
- RTL 继续支持；移动端保证 44px 触控目标、无横向页面溢出。

## 6. 验证标准

### 自动化

- 现有 581 单测全部通过；新增路由映射、状态转换、筛选 query、危险确认、保存栏状态测试。
- 现有 53 个 e2e 全部通过；旧选择器通过稳定 role/label 兼容或同步更新。
- 每个新路由至少覆盖：初始加载、空态、错误态、主动作、返回/刷新 URL 状态。
- Playwright 额外矩阵：1440×900、1280×720、390×844；中文/英文各一轮；阿拉伯语检查 `dir=rtl`。

### 人工/真实浏览器验收

逐页执行并截图：

1. 概览：KPI → 异常 → 最近操作的阅读顺序，主动作是否清晰。
2. 项目：创建 Dialog 的焦点、Escape、遮罩、校验、保存后回列表；编辑策略详情抽屉。
3. 激活码：生成核心/高级字段折叠，非法提交反馈，复制/详情/删除确认。
4. 消费与审计：筛选 → 刷新/导出 → 行详情抽屉，URL 可复制。
5. 购买中心：商品列表 → 新建 Dialog；订单状态筛选/清理确认；渠道配置完整性。
6. 系统设置：分区导航、未保存提醒、单一 StickySaveBar、保存成功/失败。
7. API 接入：章节导航、代码复制、移动端阅读。
8. 账户：用户菜单进入安全设置，改密成功倒计时退出。
9. 移动端：打开/关闭抽屉、导航后自动关闭、焦点回到 hamburger、无页面溢出。
10. 中英文/RTL：切换后页面与服务端提示同步。

## 7. 迁移策略

一次性切换用户入口，但内部采用可回退的分阶段提交：

1. 组件/壳层与路由兼容入口。
2. 业务页面按「概览 → 项目/激活码 → 消费/审计 → 购买中心 → 系统设置/API」迁移。
3. 删除旧 dashboard 组合页和重复组件，仅在确认所有路径和 e2e 通过后移除。
4. 统一清理临时 class、旧页面快照和无效测试断言。

## 8. 非目标

- 不改变现有业务规则、数据库字段、API 响应契约、权限模型和通知/支付逻辑。
- 不在本次重构中添加新的业务功能；只改善现有能力的归位、呈现和操作路径。
- 不以“引入更多组件库”代替信息架构设计；shadcn 只作为基础组件实现。
