# Roadmap（演进备忘）

> 本文件记录「已评估、暂缓实施」的事项，避免遗忘，也避免重复评估。
> 与 CHANGELOG（已完成）互补。

## 暂缓项

### 1. Next.js 15/16 升级（优先级最高）
- 现状：`next@14.2.35` 为 14.x 最终版，累计 20+ 高危公告无 14.x 补丁
- 详见：[docs/nextjs-upgrade-plan.md](./nextjs-upgrade-plan.md)
- 暂缓原因：需 React 19 + 异步 API 全量迁移，属独立专项（预计 1-2 天 + 支付渠道沙箱回归）

### 2. 管理后台 i18n
- 现状：i18n 框架（zh-CN / en-US）已覆盖公开页（首页/购买页/登录/API 文档页）；后台仪表盘全部中文
- 暂缓原因：后台组件 30+、文案数百条，翻译面大；且后台用户通常即部署者本人，中文化收益需先确认目标用户画像
- 启动建议：优先翻译「系统配置」「购买中心」两个高频工作区做试点，确认收益后再铺开

### 3. Redis 限流存储适配器
- 现状：`RateLimitStore` 接口缝已就位（`src/lib/license-api-rate-limit.ts`），默认进程内 Map
- 暂缓原因：单实例部署下无收益；接口为同步契约，Redis 需「本地读缓存 + 异步回写」适配层或多实例专项一起做
- 触发条件：真实出现多实例部署需求时立项（配合 docs/operations.md 多实例注意事项）

### 4. 通知投递重试 / 退避
- 现状：投递失败仅记录 notification_logs（可查、可人工重发邮件）
- 暂缓原因：自动重试需要后台任务调度（当前无进程内调度器），且 Webhook 重试有风暴风险需设计退避策略
- 触发条件：接到「通知没收到」的真实反馈后，优先补「失败日志一键重发 Webhook」
